# 代码清理：降速链废弃与编译修复

> 日期：2026-08-05
> 分支：`dev/pcb-v1`（pm-test 低功耗优化合并后）

---

## 1. 背景

合并 pm-test 分支的降速链废弃改动后，两个编译错误阻止增量构建通过，同时存在注释不清、死代码未标注的问题，需要统一规整。

---

## 2. 编译错误修复

### 2.1 `DEFAULT_ADVERTISING_INTERVAL` 未声明（bonding.c:291）

**现象：**
```
error: 'DEFAULT_ADVERTISING_INTERVAL' undeclared (first use in this function)
```

**根因：** `peripheral.h` 中将该宏注释掉（归入"历史遗留废弃"区块），但 `bonding.c` 的 `Bonding_ApplyPairingMode()` 仍引用。

**修复：** 取消注释 `#define DEFAULT_ADVERTISING_INTERVAL 80`，并从废弃注释区独立出来，标注为活跃宏。

### 2.2 孤立 `#endif`（peripheral.c:898）

**现象：**
```
error: #endif without #if
```

**根因：** 降速链清理时删除了 `#if` 条件编译块但遗留了对应的 `#endif`。

**修复：** 删除多余的 `#endif`。

---

## 3. 死代码识别与停用

### 3.1 Bonding_ApplyPairingMode 广播间隔设置（bonding.c:290-297）

`Bonding_ApplyPairingMode()` 中原有一块设置广播间隔为 20/30ms 或 50ms 的代码，注释称"加快 OS 后台自动重连"。

**死代码判定依据——两条调用路径追踪：**

| 路径 | 时序 | 最终生效间隔 |
|------|------|-------------|
| 上电 init | `Bonding_Init()` → `Bonding_ApplyPairingMode()` 设 20/50ms → **紧接着** `KeyGo_AdvEnterFastWindow()` 覆写为 240 ticks(150ms) → `SBP_START_DEVICE_EVT` 启动广播 | **150ms**（20/50ms 被覆盖）|
| ENCRYPT 命令 | `Bonding_ApplyPairingMode()` 设 20/50ms → 此时**已连接不广播** → 断连后 `Peripheral_LinkTerminated()` → `KeyGo_AdvEnterFastWindow()` 覆写为 150ms | **150ms**（20/50ms 被覆盖）|

两条路径下，`KeyGo_AdvEnterFastWindow()` 均会覆写 `Bonding_ApplyPairingMode()` 设置的广播间隔，该代码从未实际生效。

**操作：** 用 `#if 0` 包裹并添加详细停用原因注释，保留原文供将来恢复高占空比配对窗口时参考。关联宏 `DEFAULT_ADVERTISING_INTERVAL` 保留定义（C 预处理器宏未使用不产生 warning）。

---

## 4. 注释规整（peripheral.h）

优化 `peripheral.h` 广播间隔宏区域的注释组织结构：

```
① DEFAULT_ADVERTISING_INTERVAL = 80       ← 活跃（Bonding 配对窗口专用，80 ticks = 50ms）
② [废弃注释区] ADV_ULTRA_SLOW_* 等        ← 全部 // 注释掉，标注历史遗留
③ ADV_CONST_NOAPP/NORMAL_TICKS = 240     ← 活跃（当前主流广播，240 ticks = 150ms）
```

改进点：
- 活跃宏与废弃宏用独立区块分隔，避免误读为"全部废弃"
- 明确标注 `80 ticks = 50ms`，区分于通用广播 `240 ticks = 150ms`
- 废弃宏保留注释，注明停用日期与原因
