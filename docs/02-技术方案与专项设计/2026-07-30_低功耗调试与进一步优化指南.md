# KeyGo 固件低功耗优化专项与调测指南

> 版本：v3.36.3-fix20 基线 · 编写日期：2026-07-30
> 定位：本文不重复已落地的 P1/P2/P3-A/P5/P6 细节（见 `docs/02-技术方案与专项设计/2026-07-30_低功耗方案_P5_DCDC与全貌.md`），而是聚焦 **① 如何在无串口的自定义板上调测功耗 ② 如何确认/理解深睡 ③ 进一步降功耗的候选清单**。

---

> ## ★ 实测修正（2026-07-30 万用表串测，重要）
> 断连态实测平均电流 **3.9~5.4mA**（万用表串联电池负极）。此量级 ≈ CH582M 在 60MHz 的 **active 运行电流**，说明**断连态根本没进深睡（或深睡占比极低）**，而非 μA 级低功耗。
> - 真实断连续航：`350mAh ÷ 4.65mA(中值) ÷ 24h ≈ 3.1 天`（约 3 天，非此前基于电压掉速误估的 43 天）。
> - 这同时解释了「P6 降速后断连态耗电没降」——**不是测量精度问题，是设备压根没睡，广播降不降都无效**。
> - 根因待查（见 §5.0 诊断）：最可能 `HAL_SLEEP` 未真正生效，或某任务/中断阻止 `TMOS_SystemProcess` 进入 `CH58X_LowPower`。
> - 后续所有「天数」须以电流表 `I_avg` 为准，Li-Po 电压掉速失真不可用。

## 0. 当前功耗架构速览（已落地，备查）

| 优化 | 内容 | 影响域 |
|---|---|---|
| P1/P2 (fix12) | `HAL_SLEEP=TRUE` 深睡，主循环无需改 | 断连+连接 |
| P3-A (fix18) | 从机延迟 0→4、连接超时 100→600 | 仅连接态射频 1/5 |
| P5 (fix17) | `DCDC_ENABLE=TRUE` 内部降压 | 活跃/连接态 ≈ 直通 60% |
| P6 (fix19/20) | 两段式广播：快窗口≈10s(50ms) + 慢速待机 1s | 仅断连态 |

**断连态实际唤醒源（决定深睡占比，按频率）：**
1. 看门狗 WWDG 溢出 ISR —— **~500ms**（见 §5.1，最大固定开销）
2. 慢速广播包 —— 1s（P6）／快广播 50ms（前 10s）
3. 电量检测 `SBP_BATTERY_CHECK_EVT` —— 30s
4. 2min 校准 / TSENSE 温度采样 —— 5s 节流

**连接态额外唤醒：** 状态机轮询 125ms、RSSI 读取 500ms、周期事件 1s、连接事件（P3-A 后约 125ms×5）。

## 1. 无串口的自定义板如何调试（开发板怎么用）

自定义板未引出串口测试点 → 本地看不到 `PRINT`。调试策略分两层：

### 1.1 逻辑 / 日志层：用开发板跑 DEBUG 固件
- 开发板有物理 UART1（TXD1，引脚见开发板丝印），刷 **开启 `DEBUG`** 的同一份固件，即可在串口助手看全部日志。
- 可验证：是否进深睡（§2 的日志法）、广播是否切到 1s（`[ADV] slowed to 1000ms`）、KEY_POWER 是否断电、断连/重连流程。
- **局限**：自定义板 GPIO 已改为 GPIOB（原固件 PA4/5/6/7 是错的），开发板原引脚布局不同 →「按键/锁动作」在开发板上不可见；但 BLE 协议、深睡、广播、电源管理状态机逻辑完全一致，不受影响。

### 1.2 真实电流层：必须在自定义板串电流表
- 用 USB 电流表（或万用表串电池负极）接在电池与板子之间，读平均电流 `I_avg`。
- 芯片级深睡电流与板外围无关，因此**开发板的电流波形也能反映「是否进深睡」**（只是绝对值因外围不同不能直接搬）。

### 1.3 推荐工作流
```
开发板(DEBUG) ──验证──> 日志逻辑/深睡行为
自定义板(电流表) ──测量──> 真实 I_avg / 天数
自定义板(非DEBUG编译) ──验证──> PRINT 关掉后的真实低功耗
```

## 2. 如何确认是否进入深睡

深睡由 TMOS 在空闲时调用 `sleepCB`（已注册 `CH58X_LowPower`，`SLEEP.c:26`）。四种确认手段：

### 方法 A（最准，推荐）：电流表看电流波形
- 深睡 = **μA 级**；广播/看门狗唤醒瞬间 = **mA 级**；连接态射频更高。
- 若电流表恒在 mA 级不回落 → 没进深睡（某个任务在频繁唤醒，优先查 §5.1 看门狗）。
- 若能看到规律的 μA 基线 + 周期性 mA 尖峰 → 深睡正常。

### 方法 B（日志法，需 DEBUG）：在 `CH58X_LowPower` 加标记
- `CH58X_LowPower()`（`SLEEP.c:26`）进 `LowPower_Sleep()` 前 `PRINT("[SLEEP] enter")`、醒来后 `PRINT("[SLEEP] wake")`。
- 深睡时 CPU 停，PRINT 不工作；**醒来后第一条 PRINT 才会打** → 看「enter/wake」成对出现即证明确实睡了又醒了。
- 注意：深睡前 UART 需 flush 完再睡，否则最后一条日志可能丢。

### 方法 C（GPIO 指示，最直观）：示波器测测试脚
- 进睡前沿某空闲脚（如开发板多余 IO）`GPIO_SetBits`，唤醒后 `GPIO_ResetBits`。
- 示波器看脉冲宽度 = 睡眠时长；脉宽接近「唤醒间隔」(如 500ms/1s) 即深睡打满。

### 方法 D：开发板电流表
- 开发板串电流表，看芯片级深睡波形（与板外围无关，可类比自定义板是否进深睡）。

## 3. 进入深睡的影响与注意事项

### 3.1 当前是 sleep 模式（非 shutdown）
- `CH58X_LowPower()` 调 `LowPower_Sleep(RB_PWR_RAM2K | RB_PWR_RAM30K | RB_PWR_EXTEND)` → **RAM 全保留、RTC 跑、外部 RAM 保留**。
- 唤醒源：RTC（TMOS 定时任务）、BLE 事件、外部 GPIO 中断。
- 唤醒后从睡眠点继续，**μs 级**，RAM 内容不丢。

### 3.2 功能影响（结论：无）
- BLE 广播/连接由协议栈 RTC 唤醒保证，不受影响。
- 应用侧已在深睡前完成关键收尾：
  - `HAL_SleepInit()` 把 `GPIOA/B` 全设**输入上拉**（`peripheral_main.c:188-191`）→ 防悬空漏电；
  - 断连时 `KeyGo_ResetState()` 已断 `KEY_POWER`(PB0)、灭双 LED → 执行器不耗电。

### 3.3 副作用（仅调试相关）
- 深睡时 `PRINT`/UART **不工作**（方法 B 的局限）；
- 深睡前若有未完成的 UART 发送会丢 —— 故低功耗验证应关 `DEBUG`（见 §4）。

## 4. 调试串口 PRINT 关闭（条件编译，零成本）

### 4.1 机制
- `PRINT` 由 `#ifdef DEBUG` 控制（`CH583SFR.h:127`）：**非 DEBUG 时直接展开为空** → 零 CPU 格式化、零 UART 外设耗电。
- `UART1` 初始化与命令解析也包在 `#ifdef DEBUG`（`peripheral_main.c:192`、UART 命令分支）→ 关掉后 TXD1 不配成 UART，保持 `HAL_SLEEP` 的输入上拉态。

### 4.2 当前状态与建议
- 当前工程开启了 `DEBUG`（你能看到日志），故 UART 一直在空耗（外设使能即使空闲也耗 μA~百 μA 级）。
- **调试用 DEBUG 编译；低功耗验证/量产用非 DEBUG 编译**。切法：在 MRS 工程「编译宏 / Define」里去掉 `DEBUG` 重编即可，无需改代码。

### 4.3 验证动作（建议立即做）
- 关 `DEBUG` 重编烧录，断连态串电流表对比 `I_avg` → 量化 PRINT/UART 的耗电占比。

## 5. 进一步降低功耗的候选清单（按性价比排序）

### 5.0 ★ 首要诊断：确认是否进深睡（决定后续所有优化方向）
- **背景**：断连态实测 3.9~5.4mA ≈ CH582M 60MHz active 电流，说明**未进深睡**。在解决任何「降功耗」前，先确认根因：
  1. `HAL_SLEEP` 宏是否真为 TRUE（查 MRS 工程编译宏/配置，确认未被覆盖）。`config.h:115` 默认 `#ifndef HAL_SLEEP #define TRUE`，除非工程显式 `-DHAL_SLEEP=FALSE` 否则已开。`CH58X_LowPower`（`SLEEP.c:28`）内 `#if(HAL_SLEEP==TRUE)` 才执行 `LowPower_Sleep`，否则直接 `return 0` 不睡 → 主循环 `while(1)` 空转 → 全程 active 4mA。
  2. **★ 强嫌疑：DEBUG 版 UART 悬空引脚中断阻止睡眠**。`peripheral_main.c:192` 在 DEBUG 下初始化 UART1（你的自定义板未引串口 → TXD1/RXD1 悬空）。若 UART 接收中断使能，悬空 RX 引脚的噪声会**不停触发 RX 中断 → 持续唤醒 MCU → 几乎不睡 → 4mA**。
     - **一键验证**：关掉 `DEBUG` 重编烧录，断连态再测 `I_avg`。若电流骤降到 μA~几百 μA，**根因即此**——且这是零代码改动（量产本就该关 DEBUG）。
  3. 开发板 DEBUG 跑，在 `CH58X_LowPower()` 入口 `PRINT("[SLEEP] enter")`、出口 `PRINT("[SLEEP] wake")`；若从不见这对日志 → 调度器从不调用 sleepCB（一直有 pending 任务/中断）。
  4. 若日志成对但频率极高（每 500ms）→ 被看门狗切碎，但切碎后平均应 <1mA，与 4mA 不符 → 基本排除「切碎」，更可能是「完全不睡」。
  5. 用 GPIO 翻转 + 示波器看 `Main_Circulation`（`peripheral_main.c:156`）是否在睡，最直观。
- **只有确认「能睡」后，§5.1 看门狗才有意义**；若确认「不睡」，先解决 HAL_SLEEP/调度，收益远大于任何广播优化。

### 5.1 高优先：看门狗 500ms 唤醒（仅在确认已进深睡后优化）
- **现象**：`WWDG_SetCounter(26)`（`peripheral_main.c:131`）使 WWDG 每 ~500ms 溢出进 `WDOG_BAT_IRQHandler`。
- **问题**：断连态 500ms 一次系统唤醒，比 P6 的 1s 慢速广播还频繁，**把深睡切成 500ms 碎片**，唤醒浪涌叠加 → 广播降到 1s 后总耗电几乎不变（这就是用户实测「P6 降速后断连态 V 掉速没变」最可能的解释）。
- **候选方案**：
  - 断连态把 WWDG 周期拉长（计数器取更大值，可达数秒级）；
  - 或用 BLE 的 RTC 独立喂狗，断连态降低看门狗频率；
  - 或断连态改用更长周期的软看门狗（牺牲死机发现速度）。
- **风险**：死机发现变慢。**需电流表验证收益后再定**。

### 5.2 未用外设时钟关闭
- 确认 USB / SPI / I2C / 多余 Timer / TouchKey / ADC（若不用电池 ADC）时钟已关。
- UART 已随 `DEBUG` 关闭（§4）；其余需逐一核对 `RCC` 时钟门控。

### 5.3 TSENSE 温度采样节流
- 当前 5s 一次（`peripheral_main.c:63`，`g_tsenseTicks >= 8000`）。
- 断连态可拉长到 30s+ 或直接停（温度对锁车无实时影响）。

### 5.4 32K 时钟源权衡
- 外部 32.768K 晶振（准，多耗）vs 内部 32K RC（省，精度略差）。
- BLE 需较准 32K；若内部 RC 精度够（避免连接漂移/重连失败），可省外部晶振及驱动电流。
- **需实测连接稳定性后再决定，切勿盲目关外部晶振**。

### 5.5 连接态进一步（P3-C，未做，主战场）
- P3-A 已拉从机延迟到 4 + 连接超时 600；P3-C 候选：连接间隔拉到 500ms + 状态机轮询 125ms→500ms。
- 解锁延迟 <2.5s，仅用户接受「慢半拍」时启动。
- **注意**：实测显示连接态才是主要耗电（连接≈1.3~2×断连），故 P3-C 是进一步省电主战场。

### 5.6 电池 ADC 检测（自定义板 V04）
- 仅在 `BOARD_HAS_EXT_BAT_ADC` 开启时读 `PA3/AIN6`，默认关（回退内部 VBAT，恒~100%）。
- 若启用，读 ADC 瞬间耗电 + `PB3`(BAT_ADC_EN) 上电；可拉长采样周期 / 读完立即关使能。

### 5.7 复位源与未用引脚
- 确认复位后所有未用 GPIO 在 `HAL_SleepInit` 输入上拉生效（已做）；检查有无引脚被配置成输出且悬空/拉电流。
- `KEY_POWER`(PB0) 断连/空闲 4s 断电（已做，且断连时 `KeyGo_ResetState` 强制断）；无需再动。

## 6. 功耗验证清单（落地前必做）

| 步骤 | 动作 | 通过标准 |
|---|---|---|
| 1 | 自定义板串电流表，断连态读 `I_avg` | 应有 μA 基线 + 周期 mA 尖峰 |

| 6 | 连接态读 `I_avg`（P3-A 后） | 验证连接态仍是主要耗电，决定 P3-C 优先级 |

## 附录 B：Li-Po 电压掉速失真提醒（重要）
- 满电段（4.2V→3.7V）电压平台极平，掉压慢是**假象**，同样 V 掉速对应的实际放电可能大得多。
- **禁止**用 `电压窗口 ÷ V掉速` 算天数（会乐观数倍~数十倍）。
- 可靠天数：①电流表读 `I_avg` → `350 ÷ I_avg ÷ 24`；②满电搁置到保护电压计时。
- 相对比值仍可靠：连接态 ≈ 1.3~2× 断连态。
