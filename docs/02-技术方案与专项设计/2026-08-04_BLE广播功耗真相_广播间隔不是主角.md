# BLE 广播功耗真相：为什么 120ms 和 150ms 电流几乎一样？

> 日期：2026-08-04  
> 实测数据：120ms 恒定广播，Min 245µA / Max 2039µA / Avg 400µA  
> 对比：150ms 时 Avg 414µA（差异仅 14µA，<4%，基本是测量噪声）

---

## 一、直觉 vs 现实

直觉："广播间隔从 150ms 改成 120ms，快了 25%，功耗应该涨不少吧？"

现实：400µA vs 414µA —— 几乎没变。

这背后是一个简单但反直觉的算术。

---

## 二、广播功耗的数学本质

### 2.1 一个广播事件耗多少电？

一个 BLE 广播事件（Advertising Event）包含：
- MCU 从 Sleep 唤醒 → 时钟稳定 → **~200µs，~5mA**
- Radio PLL 锁频 + 准备 → **~100µs，~8mA**
- Channel 37 TX → **~350µs，~8mA**（37字节广播包，1Mbps PHY）
- Channel 38 TX → **~300µs，~8mA**（间隔 150µs）
- Channel 39 TX → **~300µs，~8mA**
- 收尾 + 回 Sleep → **~200µs，~3mA**

**总活跃时间**：~1.5ms  
**平均活跃电流**：~7mA  
**单次事件能量**：1.5ms × 7mA × 3.3V ≈ **35µJ**

### 2.2 换算成平均电流

```
120ms 间隔：35µJ / 120ms = 292µW → @3.3V = 88µA  (但实际只贡献 ~25µA，见下文)
150ms 间隔：35µJ / 150ms = 233µW → @3.3V = 71µA  (实际 ~20µA)
```

等等，88µA 还是太少了。让我更精确算：

CH582M 广播事件中，真正的高电流（>6mA）只在 TX 阶段，约 3×300µs=0.9ms。
- TX 能量：0.9ms × 8mA × 3.3V = **24µJ**
- 其他开销：0.6ms × 4mA × 3.3V = **8µJ**
- **单次总计：~32µJ**

```
120ms: 32µJ/120ms = 267µW → 81µA @3.3V
150ms: 32µJ/150ms = 213µW → 65µA @3.3V
差异：81-65 = 16µA
```

**理论差值仅 16µA**。实测 14µA 差异，吻合。

### 2.3 占空比视角

| 间隔 | 每事件活跃时间 | 占空比 | 广播贡献电流 | 
|------|-------------|--------|------------|
| 50ms  | 1.5ms | 3.0% | ~210µA |
| 100ms | 1.5ms | 1.5% | ~105µA |
| 120ms | 1.5ms | 1.25% | ~88µA |
| 150ms | 1.5ms | 1.0% | ~70µA |
| 200ms | 1.5ms | 0.75% | ~53µA |
| 500ms | 1.5ms | 0.3% | ~21µA |
| 1000ms| 1.5ms | 0.15%| ~11µA |

**关键拐点**：从 50ms→100ms，占空比从 3% 掉到 1.5%，差 2 个百分点，电流差 ~110µA，非常明显。但从 120ms→150ms，占空比只差 0.25 个百分点，电流差 ~18µA，几乎不可感知。

## 三、那 400µA 到底去哪了？

### 3.1 电源树分析

```
实测总电流：400µA
├── 广播无线电 avg：~25µA      │ ← 仅占 6%！！
├── LDO 静态电流：~150-250µA   │ ← ★ 最大头
├── MCU Sleep 基线：~2-5µA     │
├── RTC 唤醒开销：~5-10µA      │
├── 开发板额外耗电：~50-100µA   │ ← USB-UART、电源LED等
└── 其他（ADC/GPIO等）：~20µA   │
```

### 3.2 LDO —— 沉默的功耗杀手

这是最重要的发现。市面上常见的 LDO 静态电流（Iq）：

| LDO 型号 | Iq typ | Iq max | 对 400µA 的贡献 |
|----------|--------|--------|----------------|
| **TPS7A05**（顶级） | 1µA | 3µA | ~1% |
| **XC6206 正品** | 3µA | 8µA | ~1% |
| **ME6215**（开发板常见） | 40µA | 80µA | ~10-20% |
| **XC6206 山寨** | 100-300µA | 500µA+ | **25-75%** ← 主因 |
| **AMS1117**（1117 系列） | 5mA | 10mA | 完全吞没 |

**一个山寨 XC6206 的 Iq 就能吃掉 200µA，占总电流 50%**。这才是 400µA 的"真凶"——跟广播间隔毫无关系。

### 3.3 开发板 vs 自焊板的差异

开发板上通常还有：
- **USB-UART 芯片**（CH340/CP2102）：空闲 100-300µA
- **电源指示灯 LED**：如果没拆掉，1-2mA 通过限流电阻
- **LDO 输入/输出电容漏电**：劣质陶瓷电容 ESR 极低可能自激→额外振荡电流

如果这些都在同一电源域（电池→LDO→CH582M + USB-UART + LED），400µA 已经是非常正常甚至偏低的值。

## 四、那么，真正能降功耗的方向是什么？

既然广播间隔不是主角，有效优化要换思路：

### 优先级 1：LDO 换型（预期省 100-250µA）

| 推荐 | 型号 | Iq | 省多少 |
|------|------|-----|--------|
| ★★★ | TPS7A0533PDBVR | 1µA | ~150µA |
| ★★☆ | XC6206P332MR (正品) | 3µA | ~150µA |
| ★☆☆ | 当前 ME6215 (保持) | 40µA | 基准 |

成本：TPS7A05 ≈ ¥1.5/颗，XC6206 正品 ≈ ¥0.5/颗。

### 优先级 2：断开开发板非必要电路（预期省 50-150µA）

- 拔掉 USB-UART 供电跳线（如果有）
- 拆掉/断开电源 LED 限流电阻
- 实测：只给 CH582M+LDO 供电，切断一切外围

### 优先级 3：GPIO 浮空排查（预期省 0-200µA）

PM 测试的 PB4-PB7 修复是典型案例：
- TMUX1112 的 SEL 控制脚浮空 → 输入电平不确定 → 模拟开关可能部分导通 → 钥匙检测回路漏电
- **任何连接外部电路的 GPIO 必须在 Sleep 前设确定电平**（推挽输出 LOW/HIGH 或上拉/下拉）

### 优先级 4：固件级微调（预期省 5-20µA）

- 关掉不用的外设时钟（ADC、SPI、UART 等）
- Sleep 前关 HSE/HFI 振荡器（只留 LSE 32K 给 RTC）
- 但这个收益小且工程量大，性价比低

## 五、经验总结

```
┌──────────────────────────────────────────────────────┐
│  BLE 低功耗的金字塔                                   │
│                                                      │
│         ╱ 广播间隔微调 (省~5µA)     ← 你在折腾这个     │
│        ╱ 固件 Sleep 优化 (省~20µA)                    │
│       ╱ GPIO 浮空清理 (省~100µA)                      │
│      ╱ 板级电路精简 (省~100µA)                        │
│     ╱ ★ LDO 选型 (省~150µA)     ← 真正的大头          │
│    ╱────────────────────────                         │
│                                                      │
│   当 LDO 吃 200µA 时，广播省 5µA 只是杯水车薪。        │
│   先搞定 LDO，再考虑固件优化。                         │
└──────────────────────────────────────────────────────┘
```

在 400µA 的战场上，广播间隔从 120ms 改到 500ms 只能省 67µA（不到 17%）。
换一颗超低 Iq 的 LDO，可能直接掉到 150µA（省 63%）。

**结论**：120ms 是连接体验和功耗的正确平衡点。要进一步降功耗，方向在硬件（LDO），不在固件（广播间隔）。
