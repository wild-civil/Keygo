# 钥匙供电策略：解锁后保持通电（方案 1 / 方案 2 / 用户自选）

> 日期：2026-08-14
> 关联引脚：`PB0` = `KEY_POWER`（CH582M 自定义 PCB V03/V04，低有效 → 拉低 = 经 PMOS 给原车钥匙板供电）
> 触发场景：日产奇骏（一键启动智能钥匙版）车主的实际使用矛盾

---

## 0. 背景与问题

KeyGo 不是钥匙本身，而是「夹」在原车智能钥匙电路板上的中继器：
- `PB0` 经 PMOS 给原车钥匙 MCU 上电；
- `PB5/PB7/PB6/PB4` 去模拟「按钥匙上的按钮」输出脉冲。

原设计（`KeyGo_EnsureKeyPower` + `KeyGo_KeyPowerCheck`）意图是：
**收到命令 → PB0 拉低上电 → 发脉冲 → 空闲 `KEY_POWER_HOLD_MS`(4000ms) 后自动拉高断电（省电）。**

### 奇骏 PEPS 实测行为（用户反馈）
- 解锁/点火成功、发动机运转后，即使智能钥匙被带出车外：
  - ✅ 车不会半路熄火，油门/刹车/转向正常，可继续开；
  - ⚠️ 仪表盘报警「未检测到钥匙 / 钥匙不在车内」，蜂鸣；
  - ❗**一旦熄火，没有钥匙就再也打不着，只能叫救援。**
- 车对钥匙的认证发生在**离散动作点**：按启动键点火那一下的挑战应答；行驶中偶发重认证（失败≠断油，仅报警）。
- 致命约束：**「解锁 → 走到车边 → 坐进 → 踩刹车点火」整段时间内，钥匙必须一直在场可应答。**

### 矛盾点
当前固件若真按「解锁脉冲发完 4s 后断电」执行，则解锁后磨蹭 >4s 才点火 → 钥匙已死 → 点火时车呼叫不到 → 打不着。
**更糟的是**：`KeyGo_KeyPowerCheck()` 当前在整个工程中**没有任何调用点（死代码）**，即 PB0 一旦首次上电就**永远不会自动断电**。这意味着：
- 现状 = 实际上「一直通电」（无期限），只是**没有显式语义、没有可配置、也没有锁车/断连兜底断电**。
- 这是隐患：人锁车走了、手机断连了，钥匙仍被白白供电。

## 1. 三个候选方案

| 方案 | 含义 | 优点 | 缺点 |
|---|---|---|---|
| **方案 1（限时）** | 解锁后 PB0 保持低一段固定时长（如 15s/30s/可调），到期断电 | 实现最简单；对所有车型/电瓶车通用；断电确定性好 | 时长设短了仍可能不够（冬天戴手套/搬东西磨蹭超时才断电）；设长了白耗电 |
| **方案 2（常保持）** | 解锁后 PB0 一直低，直到收到 `LOCK`（重新上锁）或「断连超时」才断电 | 完美覆盖「解锁→点火」任意时长；语义最自然 | 已锁车/人离开后若触发不到断电仍耗电；必须有可靠的 LOCK + 断连双兜底 |
| **用户自选** | APP 里选「解锁后限时 N 秒」或「解锁后一直保持（到锁车/断连）」 | 灵活，适配汽车/电瓶车不同场景 | 多一个配置项 + DataFlash 持久化 + 下发逻辑 |

### 关键洞察（修正对方案 2 的担忧）
方案 2 的「一直保持」**不是真·永远通电**，它有明确的断电触发点：
1. **重新 LOCK**（`g_keyState` 回到 `KSTATE_LOCKED`）：手动锁车 / RSSI 远离自动锁 / 断连兜底锁（`SBP_DISCONNECT_LOCK_EVT` → `KeyGo_Lock`）；
2. **断连超时**：手机 BLE 掉线超过 `g_cfgDisconnectLockMs` 触发断连兜底锁（同上，最终归到 LOCK）。

即「一直保持」=「你用车期间保持，锁车/离开即断」，并不无脑耗电。

## 2. 落地形态建议（推荐）

**推荐：方案 2 为汽车默认 + APP 用户可二选一（限时 / 常保持）。**

- 新增配置维度 `KEY_POWER_MODE`：
  - `TIMEOUT`：解锁后保持 `KEY_POWER_HOLD_MS` 再断电（电瓶车用户 / 想要确定断电的用户选这个，默认 30s）；
  - `HOLD_UNTIL_LOCK`：解锁后保持到 `LOCK` 或「断连超时兜底锁」触发才断电（汽车用户选这个）。
- APP 端提供开关 + 限时秒数输入（如 8/15/30/60s）。
- 断电统一收敛到 `KeyGo_KeyPowerCheck()`（当前死代码，需接入状态机周期任务），判定逻辑按 `KEY_POWER_MODE` 分支：
  - `TIMEOUT`：到 `g_powerOffAtMs` 即断（现有逻辑）；
  - `HOLD_UNTIL_LOCK`：`g_keyState == KSTATE_LOCKED` 才允许断；解锁/骑行态期间不主动断。

### 断电触发点对接（已核实代码）
- `KeyGo_Lock()`（`peripheral.c:1221`、断连兜底 `peripheral.c:710`、骑行退出链 `keygo_core.c:533`）都会把 `g_keyState = KSTATE_LOCKED`。此处可直接调 `KeyGo_RequestKeyPowerOff()`（方案 2 专用：仅当模式=HOLD_UNTIL_LOCK 时立即拉高 PB0）。
- 普通周期轮询里仍跑 `KeyGo_KeyPowerCheck()` 处理 `TIMEOUT` 模式的到点断电。

### 当前必须修的隐藏 bug
`KeyGo_KeyPowerCheck()` 未被任何任务调用（`keygo_core.c:586` 定义、`keygo_core.h:71` 声明，零调用点）。
→ 无论选哪个方案，**都必须把它接入周期任务**（如 `KeyGo_ProcessStateMachine` 每拍或 `SBP_PERIODIC_EVT`），否则策略不生效。

## 3. 出厂默认行为待定（需用户拍板）

汽车场景默认选哪个？

- **A. 方案 2（解锁后保持到锁车/断连）**：最贴合奇骏，解锁后无论磨蹭多久去点火都安全；离开锁车即断电不浪费。
- **B. 方案 1 加强版（解锁后限时 30s）**：简单确定性好，但 30s 对某些场景偏紧、且「已锁车但手机还在」仍白白供 30s。

**倾向建议**：汽车默认用 **方案 2（HOLD_UNTIL_LOCK）**——它覆盖了「任意磨蹭时长去点火」的刚需，又有 LOCK/断连双兜底断电，不会无脑耗电。电瓶车用户可在 APP 切到 TIMEOUT。
