## 一、最终设计（方案 C 简化版，已与用户确认）

- **两档**（非用户最初设想的"限时+常保持二选一任意秒数"，进一步简化为固定档）：
  - `kpm = 0` → **TIMEOUT**：解锁/上电后固定保持 **`KEY_POWER_TIMEOUT_MS = 15000`(15s)**，到期自动断电。
  - `kpm = 1` → **HOLD_UNTIL_LOCK（默认，汽车）**：解锁/骑行后 PB0 保持低，直到 `KSTATE_LOCKED`（手动锁 / 断连兜底锁 / 骑行退出锁）才拉高断电。
- **只存 1 字节** `g_cfgKeyPowerMode`（0/1），塞进 DataFlash `buf[15]`（原空闲），**buf 不扩、校验循环不动**（XOR 仅覆盖前 12 字节，不含 13~15）。
- 配置属性 = **设备级参数**（与 cooldown_ms / autolock 同类）：FF01 下发 → 写 DataFlash → FF02 回显。所有手机共用，连接时**不下发**，改了才 `updateConfig` 下发。
- **默认 = 1（HOLD_UNTIL_LOCK）**：编译期 `KEY_POWER_MODE` + LoadConfig 旧格式兜底（buf[15]=0 → 映射默认 1）。

## 二、固件侧改动（CH582M_BLE_Slave，keygo_core.c + config.h）

### 2.1 config.h（顶部宏区）
- 新增 `KEY_POWER_MODE`(默认 1)、`KEY_POWER_TIMEOUT_MS`(15000)。保留原 `KEY_POWER_HOLD_MS`(4000，现仅作历史参考，TIMEOUT 模式用新 15s 宏)。

### 2.2 全局变量（keygo_core.c ~L126）
- 新增 `uint8_t g_cfgKeyPowerMode = KEY_POWER_MODE;`（默认 1）
- 电源区新增 `static uint8_t g_powerHoldForever = 0;`（HOLD 模式标志）

### 2.3 KeyGo_EnsureKeyPower / KeyGo_KeyPowerCheck（~L561）
- `EnsureKeyPower`：上电后按 `g_cfgKeyPowerMode` 分支 —— TIMEOUT 设 `g_powerOffAtMs = now + 15000` 且清 `g_powerHoldForever`；HOLD 设 `g_powerHoldForever=1` 且 `g_powerOffAtMs=0`。
- `KeyPowerCheck`（已被 `SBP_PERIODIC_EVT` 周期调用，非死代码）：`g_powerHoldForever` 为真则直接 return（不通电截止）；否则按超时断电。

### 2.4 KeyGo_GPIO_PulseEnd（~L546）
- LOCK 动作脉冲结束（`g_keyState == KSTATE_LOCKED` 且 `g_powerHoldForever`）→ 断电 + 清 `g_powerHoldForever`。Unlock/Ride/Trunk/Other 脉冲结束保持通电。

### 2.5 KeyGo_LinkReset（~L655）
- 断连复位处补 `g_powerHoldForever = 0`（断连即终止 HOLD 通电，符合"断连兜底锁"语义）。

### 2.6 KeyGo_ParseConfig（~L1336）+ changed 块
- 新增 `kpm` 键（长度 3）解析，`val!=0 → 1`，置 `kpm_changed` + `changed`。
- changed 块：`if (cooldown_changed || kpm_changed) KeyGo_SaveConfig();`

### 2.7 LoadConfig / SaveConfig（~L1455 / ~L1603）
- Load：buf[15] 读出 mode，0 → 映射编译期默认(1，兼容旧格式)，1 → 1，其他 → 1。
- Save：buf[15] = (mode==0)?0:1；EEPROM_WRITE 长度仍为 16（buf[15] 在 16 字节内）；校验 XOR 仍覆盖前 12 字节。

### 2.8 FF02 JSON（~L963 / ~L1003）
- 格式串末尾加 `,"kpm":%d`；snprintf 参数列表末尾加 `(int)g_cfgKeyPowerMode`。当前 JSON ~210B + 约 10B 仍在 STATUS_JSON_MAX_LEN=272 内。

## 四、关键设计说明

1. **为何 HOLD 模式"不是真·永远通电"**：断电触发点 = ① 手动 LOCK（脉冲结束 PulseEnd 检测 KSTATE_LOCKED）② 断连兜底锁（KeyGo_Lock 走脉冲→PulseEnd 断电；直接 LinkReset 也断电）③ 骑行退出链（SBP_RIDE_EXIT_LOCK_EVT → KeyGo_Lock → 同上）。即"用车期间保持、锁车/离开即断"。
2. **TIMEOUT 模式用 15s 硬编码**：用户确认钥匙限时可选项"够用就行"，15s 覆盖电瓶车/普通遥控"按一下就完"场景；省去 holdSec 第二字段与 buf 扩容。
3. **FF01 必须 + FF02 必须 + DataFlash 必须**：三者一条链路，缺一不可（分析见前置文档）。
4. **旧固件兼容**：无 `kpm` 字段的旧设备，新 APP 收不到 → `keyPowerMode=-1` 显示"同步中"，UI 不崩；旧格式 buf[15]=0 → Load 映射默认 HOLD(1)，行为保持。
5. **★ No-App 模式同样遵循 kpm（2026-08-15 用户确认需求）**：kpm 是设备级 DataFlash 参数（buf[15]），不依赖任何手机在场。无 App 模式的状态机自动解锁/骑行（`KeyGo_Unlock`/`KeyGo_Ride`）第一行即 `KeyGo_EnsureKeyPower()`，读同一个 `g_cfgKeyPowerMode`。因此：在 APP 选 `kpm=1`（解锁后保持），即便不打开手机、揣兜里走近，设备也能靠 RSSI 状态机自动解锁并让钥匙一直通电（HOLD），车即可检测到钥匙——这正是用户想要的"无 App 也能让车检测到钥匙"。无需单独为 No-App 分支写逻辑，当前实现已满足。

## 五、实测验证要点（待真机）
- 汽车场景：解锁 → 30s 后才点火 → 车能检测到钥匙（PB0 仍低，HOLD 生效）。
- 锁车：手动 LOCK → 钥匙断电（PB0 拉高）。
- 断连：手机离开 → 断连兜底锁 → 钥匙断电。
- 电瓶车：切 kpm=0 → 解锁 15s 后自动断电。
- FF02 回显 `kpm` 字段实时正确；改后重连仍保持（DataFlash 持久化）。
