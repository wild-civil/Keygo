# KeyGo 低功耗方案 P1+P2（v3.36.3-fix12，2026-07-30）

## 目标
在不牺牲任何功能的前提下，让设备「放着 / 已断开」时进入深度睡眠，大幅省电。
连接态（需要自动解锁响应）保持原有功耗，P3（拉长连接间隔/从机延迟）暂缓。

## 现状梳理（动手前）
- 休眠框架 SDK 已自带（`HAL_SLEEP` + `CH58X_LowPower`），但 `config.h` 里 **`HAL_SLEEP = FALSE`**，等于从未开启，CPU 一直 60MHz 满频空转。
- 休眠由 BLE 库的 `cfg.sleepCB = CH58X_LowPower` 驱动（`HAL/MCU.c:122-125`），`TMOS_SystemProcess()` 在无待处理任务时自动调用，**主循环 `Main_Circulation` 无需改动**。
- 内部 32K RTC 已开（`CLK_OSC32K=1`），休眠计时基础具备。
- 继电器自动断电（空闲 4s，`keygo_core.c` `KeyGo_KeyPowerCheck`）已落地。
- 断连时 `Peripheral_LinkTerminated` 早已停掉连接态专有高频任务：周期状态 1s / RSSI 500ms / 状态机 125ms（`peripheral.c:853-855`），并 `KeyGo_ResetState()` 关掉 `KEY_POWER`（继电器模块断电）。

## 本次改动（P1+P2）
1. **`HAL/include/config.h`：`HAL_SLEEP` 由 `FALSE` → `TRUE`**
   - 这一行是唯一的开关性改动。开启后 `cfg.sleepCB` 注册，BLE 库在无事件时自动 `CH58X_LowPower()` 深度睡眠。
   - 补充注释：休眠机制、GPIO 安全、软看门狗兼容条件、调试提示。
2. **`APP/include/keygo_core.h`：固件版本 `3.36.3-fix11` → `3.36.3-fix12`**。
3. **`APP/peripheral.c`：`Peripheral_LinkTerminated` 任务停止处补 P2 注释**，说明断连后只剩「广播 + 电量轮询(30s) + 2min 校准」三类稀疏唤醒 → 可在广播包之间深度睡眠。

## 安全性论证
- **GPIO 电平安全**：`main()` 在 `HAL_SLEEP=TRUE` 时先把 GPIOA/B 全设输入上拉（`peripheral_main.c:189-190`），但 `Peripheral_Init → KeyGo_GPIO_Init`（`keygo_core.c:218`）随后把控制脚 `PB4/5/6/7/PB0/PB14/PB15` 配回输出（ModeOut_PP_5mA）并设定电平。睡眠期间 GPIO 输出锁存保持，继电器/LED 电平不丢、不 float。已真机确认引脚配置完整。
- **软看门狗兼容**：自定义软看门狗（WWDG，~500ms 周期，连续 5 次主循环不报到 `g_mainLoopAlive` → 软复位）。深度睡眠时主循环卡在 `TMOS_SystemProcess` 内不执行，**但**断连后设备持续广播（间隔 < 2.5s），每次广播唤醒都会跑主循环并置 `g_mainLoopAlive=1`；连接态唤醒更频繁。故看门狗不会误判死机复位。
  - ⚠ 约束：若将来把广播间隔调到 > 2.5s，或实现「完全停广播 deep-park」，需重新评估看门狗，否则长睡会触发误软复位。
- **DCDC 仍 FALSE**：`config.h:82` `DCDC_ENABLE=FALSE`（VSW 直连 VDCID 的旁路接法，开 DCDC = 开关节点短接 VDD → 短路/损芯片风险）。与本次休眠无关，保持不变。

## 功耗收益
- 断连/待机态：CPU 在广播包之间深度睡眠（仅广播射频 + 30s 电量轮询 + 2min 校准唤醒），相比此前 60MHz 空转，电流量级从 mA 级降到 μA 级（典型 BLE 外围待机）。
- 连接态：状态机 125ms / RSSI 500ms / 周期 1s 仍持续唤醒 → 不省电（保留自动解锁响应，属预期；P3 才动）。

## 验证清单（真机）
1. MRS 重编 → 烧录。
2. 控制页 `[INIT]` 确认 `FW Version: 3.36.3-fix12`。
3. 断连静置：电流表测待机电流应显著下降（深度睡眠）；手机靠近自动重连正常。
4. 连接态：自动解锁/锁车/骑行响应与 fix11 一致（不受影响）。
5. 软看门狗不误复位：长时间待机（>10s）不重启（无 LED 三闪/复位循环）。
6. 控制脚/LED 睡眠不丢电平：待机后继电器控制脚保持低（不吸合）、LED 灭。

## 后续（P3，未做，待定）
- 连接中也省电：拉长 BLE 连接间隔 + 从机延迟（slave latency）+ 自动解锁轮询 125ms → ~500ms。
- 代价：手机远离时自动解锁慢半拍。需用户拍板产品取舍。

## 关键坑（已写入 MEMORY）
- TMOS 自定义事件位只用 `0x0001~0x4000`，绝不用 `0x8000`（=OSAL `SYS_EVENT_MSG` 保留位），详见 LED 永久常亮 fix11 复盘。
- `0x8000` 事件位会被 `Peripheral_ProcessEvent` 顶部 `SYS_EVENT_MSG` 分支提前 return 吞掉，自定义 handler 永不可达。
