# 2026-08-17 · 1007 固件侧 ATT 忙窗量化诊断打点

## 背景
App 侧 `writeBLECharacteristicValue` 偶发 `errCode 10007`（OS 本地拒绝：该特征值写属性位尚未就绪）。
此前结论（待证伪/证实）为「Android GATT 缓存冷窗 4.2s」，但 18:48 日志显示**服务发现已完成仍持续 1007**，
且该结论从未被真机量化验证。为「从固件侧真解决 1007」，先在固件加**高精度时间戳打点**，
量化两个窗口的真实耗时，再据数据决定治本改动（而非继续在 App 侧空转）。

## 打点开关
`APP/include/keygo_core.h` 顶部：取消注释 `// #define KEYGO_1007_DIAG` 即开启全部诊断。
默认**关闭**，不影响量产固件体积与时序。

## 量化指标（PRINT 输出，连串口/调试基座可读）
| 标记 | 含义 | 对应窗口 |
|------|------|----------|
| `[1007DIAG] CONNECTED` | 连接建立时刻 | 窗口①起点 |
| `[1007DIAG] FIRST FF03(NONCE)` | 首个 FF03(NONCE) 写到达 | 窗口①耗时 = dtConn |
| `[1007DIAG] AUTH:OK sent` | AUTH:OK 发出 + 首写→AUTH 耗时 | 窗口①闭合 / 窗口②起点 |
| `[1007DIAG] FIRST FF01(cfg) AFTER AUTH` | AUTH 后首个 FF01(配置) 写到达 | 窗口②耗时 = dtAuth |
| `[1007DIAG] ATT write CB slow` | 单次 ATT 写回调耗时 > 10ms | 看是否固件侧阻塞 |

## 打点位置（跨文件，经 keygo_core.h extern 共享）
- `peripheral.c` `Peripheral_LinkEstablished`：记 `g_diagConnEstMs`，重置全部窗口标志。
- `gattprofile.c` `simpleProfile_WriteAttrCB`：
  - 首部记 `cbStart`（单次回调计时起点）；
  - FF03 case：首个 NONCE 写到达记 `g_diagFirstFf03Ms`；
  - FF01 case（仅 `g_diagAuthed` 后）：首个配置写到达记 `g_diagFirstFf01Ms`；
  - 尾部：回调耗时 > 10ms 时 PRINT（定位固件侧阻塞）。
- `bonding.c` `Bonding_HandleAuthResp` AUTH:OK 分支：记 `g_diagAuthOkMs`、置 `g_diagAuthed=1`。

## 数据解读与治本决策树
1. 若 **窗口① (dtConn) 很短（< 300ms）但 App 仍撞 1007** → 证实 1007 不在固件 ATT 处理，
   是 Android 对 FF03 特征值缓存未就绪 → 治本在 App 重试窗口（已最优，无需改）。
2. 若 **窗口① 很长（> 1s）** → 固件在连接初期忙（协议栈/服务发现/MTU 协商），可考虑：
   提前完成 GATT 表注册、降低连接初期任务负载。
3. 若 **窗口② (dtAuth) 很长（> 1s）** → AUTH:OK 后固件仍忙（FF02 推送/状态机切换抢占 ATT），
   可错峰 FF02 首推、降低 AUTH 后瞬间负载。
4. 若 **ATT write CB slow 频繁出现 > 50ms** → 写回调路径上有阻塞（如长写重组/应用层同步处理），
   需异步化。

## 使用步骤
1. `keygo_core.h` 取消 `KEYGO_1007_DIAG` 注释。
2. MRS 编译烧录（PCB-V1 需重新制作自定义调试基座，manifest versionCode +1）。
3. 手机连设备 → 复现 1007 场景 → 抓串口/调试基座日志，过滤 `[1007DIAG]`。
4. 据上表数据填「决策树」定位真因 → 实施治本改动 → 关闭开关重新量产验证。

## ★ 实测结论（2026-08-17 19:02 真机数据，已推翻"Android 缓存冷窗"假说）
### 数据（串口过滤 `[1007DIAG]` + App 日志对齐）
```
[19:02:50.931] [FF02] NOTIFY FAIL ret=16 (ATT忙)     ← 固件自己撞 ATT 事务槽忙
[19:02:53.462] [1007DIAG] FIRST FF01(cfg) AFTER AUTH t=196368 dtAuth=2843 (window② elapsed)
[19:02:53.485] [1007DIAG] ATT write CB slow: uuid=FF01 method=18 len=70 cost=22 ms
App: 48.792 FF03 NONCE 10007 ×7 → 49.685 命中（窗口①≈0.9s）
App: 53.266 FF03 配置成功；53.266 FF03 RSSISET 10007 ×14 → 55.729 命中（窗口②≈2.5s）
```
### 真因（定论）
**1007 不是 Android 缓存问题，是固件 ATT 事务槽被 FF02 周期推送(1s/次,224B) 占满，把 App 的 NONCE/AUTH/配置/RSSISET 写请求挤成协议栈拒绝。**
- 铁证①：固件自己报 `NOTIFY FAIL ret=16 (ATT忙)`（`blePending`），与 Android 无关 → ATT 层真忙。
- 铁证②：窗口② `dtAuth=2843ms` 内 FF02 疯狂撞忙、FF01 写回调耗时 22ms，App 的 FF03 RSSISET 直到 2.5s 后才命中。
- **旧"Android GATT 缓存冷窗 4.2s"假说被推翻**——服务发现早完成、App 重试已最优，问题在固件侧占槽。

### 治本改动（已落地 `keygo_core.c`）
**FF02 ATT 事务槽自适应退避**：`KeyGo_NotifyStatus` 检测到 `simpleProfile_Notify` 返回 `blePending` 时，
设 `s_ff02BackoffUntil = now + FF02_BACKOFF_MS(600ms)`；函数入口加守卫，`now < s_ff02BackoffUntil` 时整函数
return（不构造/不发送 FF02 状态 JSON），把事务槽让给 App 写。忙窗结束自动恢复 1s 心跳。
- **握手 RAW 队列（NONCE/AUTH:OK）不受影响**：走独立 `SBP_DEFERRED_RAW_EVT` + 重试，且退避仅加在 `KeyGo_NotifyStatus` 入口，握手必需报文照常发。
- 事件驱动状态推送（解锁/锁车回显）在忙窗内可能延迟 ≤600ms，但解锁脉冲是 GPIO 硬件动作不依赖回显，可接受。
- 实测预期：窗口② 内 FF02 多次撞忙→多次退避→App 写畅通→RSSISET 命中时间从 ~2.5s 降到百 ms 级。

## ★ 二次定位（2026-08-17 19:08 验证→App 侧窗口①暴涨根因）
### 现象
固件退避生效后 RSSISET 零 1007（治本成功），但**窗口① dtConn 从 0.9s 暴涨到 5.98s**。
串口铁证：CCCD 订阅在 38.58s 才完成、NONCE 39.06s 才发 → App 连接后 ~5.5s 没订阅 FF02、也没发 NONCE。

### 真因（App 侧）
`stores/ble.js` 连接成功后**先同步发起 `readSerialNumber(targetId, 5000)`**（内部走
`getBLEDeviceServices`+`getBLEDeviceCharacteristics`+读 FF04，全程占 GATT 串行链 `_gattChain`），
**再 `setTimeout(800)` 后才发起 FF02 订阅**（经 `enqueueWrite` 也走 `_gattChain`）。
两路径共用一条串行链 → FF02 的 CCCD 写被排在 `readSerialNumber` 那串 GATT 操作（~5s）之后 →
订阅晚 ~5s → NONCE 跟着晚 → 窗口① 暴涨。

### 治本改动（已落地 `stores/ble.js`）
- **重连路径**（~L2071）：去掉 `setTimeout(800)`，FF02 订阅改 IIFE **立即发起**（先于 `readSerialNumber`），
  让 CCCD 写尽早入链队首；SN 读并行但在其后。
- **首连路径**（~L2287 `_finalizeConnection`）：去掉 `setTimeout(800)`，直接 `this._enableStatusNotify()` 立即订阅。
- 已知 UUID 常量，FF02 订阅无需等服务发现，提前安全；订阅就绪即驱动自动 AUTH，SN 读慢不影响鉴权主链。
- 预期：窗口① 从 5.98s 压回 ~1s（与 19:02 那次 0.9s 同量级）。

## 注意
- 打点**不改任何业务逻辑**，仅增 PRINT + 时间戳记录，可安全来回开关。
- 诊断变量均为模块级，零并发风险（BLE 单连接串行）。
- 完事务必关闭 `KEYGO_1007_DIAG` 再出量产固件，避免串口刷屏与微小时序扰动。
