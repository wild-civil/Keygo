# 死滚动与 100vh 陷阱：min-height:100% + box-sizing:border-box

> 来源：KeyGo App 修复 fix11.4（commit 0994c9c），四页根 `.page-root` 由 `min-height:100vh` 改为 `min-height:100%` + `box-sizing:border-box`，消除"死滚动"（页面多出一段滑不动 / 多余滚动区）。
> 目标：讲清移动端 `100vh` 在滚动容器里的坑，以及 `box-sizing` 对 `min-height` 的影响。UI 复盘素材。

---

## 0. 现象

控制页 / 配置页等四个 tab 页，进入后页面底部会多出一段"死区"——能滑但滑不到内容，或内容已经到底却还能继续滚一段空白。用户侧表现为"页面晃、底部留白、滚动不跟手"。

---

## 1. 架构背景：真正的滚动容器是 scroll-view

`main.vue` 用 `swiper` 包了 4 个 `swiper-item`，每个里面是一个 `<scroll-view scroll-y>`：

```html
<swiper class="tab-swiper" :current="tabIndex">
  <swiper-item>
    <scroll-view scroll-y class="swiper-scroll"><IndexPage /></scroll-view>
  </swiper-item>
  ...
</swiper>
```

也就是说，**页面滚动由 `scroll-view` 提供**，不是页面根节点自身。页面组件（如 `config.vue`）的根 `.page-root` 只是 `scroll-view` 里的一段内容。

---

## 2. 根因一：min-height:100vh 撑破了 scroll-view

修复前各页根：
```css
.page-root { min-height: 100vh; }   /* ❌ 旧 */
```

- `100vh` = 整个视口高度。但内容已经在 `scroll-view` 里，`scroll-view` 本身已可滚动。
- 页面根硬设 `至少一屏高`，叠加 scroll-view 的滚动能力 → 内容区被人为撑到 ≥ 屏高，超出实际可视 → **死滚动**。
- 正确做法：让页面根"填满 scroll-view 的内容高度"而非"填满视口"，即用相对父容器的 `100%`：
```css
.page-root { min-height: 100%; }    /* ✅ 新：相对 scroll-view 内容高度 */
```
> 注意：`min-height:100%` 的 `100%` 是相对**父容器高度**。此处父级 `scroll-view` 给了确定内容高度，所以 `100%` 能正确撑满。

---

## 3. 根因二：没开 border-box，padding 又撑出残余死滚

仅改 `100%` 还不够，因为页面根有纵向 padding：
```css
.page-root {
  min-height: 100%;
  padding: 30rpx 30rpx 30rpx;   /* 纵向 30rpx */
}
```
- 默认 `box-sizing: content-box`：`height` 只算内容区，**padding 额外叠加在外**。
- 于是实际高度 = `100% + 30rpx(上) + 30rpx(下)` → 又溢出一点点 → **残余死滚**。
- 修复：加 `box-sizing: border-box`，让 `min-height:100%` **已含** padding：
```css
.page-root {
  min-height: 100%;
  box-sizing: border-box; /* ✅ border-box 使 min-height:100% 已含纵向 padding */
  padding: 30rpx 30rpx 30rpx;
}
```

实际代码（`config.vue` 等四处一致）：
```css
/* v3.36.3fix11.4 补充: border-box 使 min-height:100% 已含纵向 padding，消除 padding 残余死滚 */
min-height: 100%;
box-sizing: border-box;
```

> 对比：`App.vue` 的 `.app-root { min-height: 100vh }` **保留不动**——因为它是真正的全屏外壳根（不在 scroll-view 内），用 `100vh` 撑满整屏是合理的。坑只发生在"嵌在滚动容器里的内容页根"。

---

## 4. 知识点速记

| 概念 | 要点 |
|---|---|
| `100vh` | 相对**视口**高度。移动端浏览器 URL 栏会导致 `100vh` 实际大于可见区（底部被遮）；嵌在 scroll-view 里更不该用 |
| `min-height:100%` | 相对**父容器**高度，需父级有明确高度才生效 |
| `box-sizing: content-box`（默认） | `height` 不含 padding/border → padding 额外撑高 |
| `box-sizing: border-box` | `height` 含 padding/border → 设 `100%` 不会被 padding 撑破 |

---

## 5. 经验法则

- **滚动内容页**：`min-height:100%` + `box-sizing:border-box`，不要 `100vh`。
- **全屏外壳根**：可用 `100vh`（确为整屏根时）。
- 任何给元素设 `height/min-height:100%` 且带 padding 的场景，顺手加 `box-sizing:border-box`，避免"看起来对、实际溢出"的幽灵滚动。
- 移动端尽量避开 `vh`，尤其 iOS Safari 的地址栏伸缩会让 `100vh` 跳动。
