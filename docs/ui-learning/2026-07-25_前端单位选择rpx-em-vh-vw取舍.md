# 前端单位选择：rpx / em / vh-vw 的取舍

> 来源：KeyGo App 多处实践——布局用 `rpx`、文字缩进用 `em`、外壳根用 `100vh`、滚动内容页改用 `100%`（见《死滚动 100vh》篇）。目标：把"什么时候用哪个单位"讲成可复用的决策表。UI 复盘素材。
> 关联文档：《padding-left 与 text-indent 悬挂缩进》（em 实战）、《死滚动 100vh 与 box-sizing》（vh 踩坑）。

---

## 0. 四个常用单位

| 单位 | 参照物 | 典型场景 |
|---|---|---|
| `rpx` | 屏宽（uni-app：750rpx = 屏宽） | 布局间距、尺寸、栅格 |
| `em` | 当前元素 `font-size` | 文字排版缩进、行高、与字号成比例的留白 |
| `rem` | 根 `font-size`（uni-app 下 rpx 已承担响应式，rem 少用） | 全局字号基准（较少用） |
| `vh` / `vw` | 视口高 / 宽 | 全屏外壳、需要锁视口的场景（谨慎） |

---

## 1. rpx：uni-app 的响应式像素（布局首选）

- `750rpx = 屏幕宽度`，编译时按设备屏宽自动换算成 px → 一套尺寸跨端自适应。
- 用于：页面 padding、卡片间距、按钮尺寸、图标大小等**布局类**数值。
- 优点：不用自己写媒体查询，天然响应式。
- 局限：它是"绝对响应式像素"，**不带语义**——用来做"相对字号几倍"的缩进会失去随字号缩放的能力（见下）。

---

## 2. em：相对字号，排版缩进的神器

- `1em = 当前元素 font-size`。KeyGo 里 `.step-desc { font-size:22rpx }`，于是 `1em = 22rpx`、`2em = 44rpx`。
- 用于：悬挂缩进 `padding-left:3em; text-indent:-1em`、首行缩进 `text-indent:2em`、行高 `line-height:1.5`、与字号等比例的间距。
- 优点：**随字号等比缩放**。改 `.step-desc` 字号，所有 em 缩进自动跟着变，不用逐个改数值——比写死 `rpx`/`px` 专业。
- 经验法则：**布局间距用 rpx，文字排版的缩进/行高用 em**。

---

## 3. vh / vw：锁视口，但移动端有坑

- `100vh` = 整个视口高。移动端浏览器（尤其 iOS Safari）地址栏伸缩时，`100vh` 会**大于实际可见区**（底部被遮/跳动）。
- 更致命的是**嵌在滚动容器里**（如 KeyGo 的 `scroll-view`）：内容页根用 `min-height:100vh` 会撑破 scroll-view，造成**死滚动**（详见《死滚动》篇）。
- 结论：**滚动内容页别用 vh**，改用 `min-height:100%`（相对父容器）+ `box-sizing:border-box`。`vh` 只留给真正的全屏外壳根（且要接受移动端地址栏的细微差异）。

---

## 4. 决策表（落地直接用）

| 我要… | 用 | 别用 |
|---|---|---|
| 页面/卡片间距、按钮尺寸 | `rpx` | `px`（失响应） |
| 文字首行缩进、悬挂缩进 | `em` | `rpx`（不随字号缩放） |
| 行高 | `em` 或纯数字（`1.5`） | — |
| 全屏外壳根高度 | `100vh`（谨慎） | — |
| 滚动内容页高度 | `min-height:100%` + `border-box` | `100vh`（死滚） |
| 相对屏宽的宽 | `vw` / `rpx` | — |

---

## 5. 经验法则

- **rpx 管布局，em 管排版**：这是 KeyGo 里最稳的分工。
- 任何 `height/min-height:100%` + 带 padding 的元素，加 `box-sizing:border-box`，避免 padding 撑破（单位选对也要盒模型配合）。
- 看到"看着对、实际溢出/错位/底部留白"，先怀疑单位：`vh` 在滚动页、`px` 失响应、`rpx` 做排版缩进不随字号变，是三大常见源。
